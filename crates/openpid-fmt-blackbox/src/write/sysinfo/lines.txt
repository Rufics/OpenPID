# The system-information header lines of Betaflight: every line some release
# writes after the field definitions, each written once, in an order of which
# the order of every release is a part.
#
#   name | releases | conditions
#
# releases    the releases that write the line: `all`, one (`4.2`), a span
#             (`4.4-4.5`), from one on (`4.3-`: 4.3 and every later release),
#             or several of these with commas. A line that changed its
#             conditions, or its place among the others, stands once for each.
# conditions  the build options and run-time conditions that must all hold
#             (the names of `Build` in `mod.rs`, which gives the firmware's
#             macro for each); none: every build writes the line.
#
# Read from `blackboxWriteSysinfo` in `src/main/blackbox/blackbox.c`, the
# parameter names from `src/main/fc/parameter_names.h`, at these tags of the
# Betaflight repository (`tools/betaflight-blackbox/extract.py` lists them):
#
#   4.2          4.2.11
#   4.3          4.3.2
#   4.4          4.4.3
#   4.5          4.5.0 ... 4.5.5 (the same lines in all six)
#   2025.12      2025.12.1 ... 2025.12.5 (the same in all five)
#   2026.6       2026.6.1, 2026.6.2 (the same in both)
#   2026.12-dev  master at 4b1520e
#
# Checked against the header lists of the fixtures of 4.2.0, 4.2.8, 4.2.11,
# 4.5.1 and 2025.12.2 (`mod.rs`, `the_tables_list_what_real_builds_write`).
