# ADR-0003: Числова політика та валідація математики

Статус: прийнято (2026-11-04)

## Рішення
1. Усі обчислення — `f64`. Сирі лічильники логу — цілі до моменту масштабування; масштаб застосовується один раз.
2. Валідність даних — явна бітова маска у `Series`; NaN не використовується як сигнал.
3. Одиниці вимірювання — enum `Unit` у кожному `Channel`; аналіз відмовляється працювати з неочікуваною одиницею (помилка, не мовчазне перетворення).
4. Вікна та PSD нормуються явно (coherent gain, ENBW); у виході вказано одиниці (`(°/s)²/Hz`, `°/s rms`).
5. Нерівномірний час: ресемплінг на рівномірну сітку з лінійною інтерполяцією у межах допуску; прогалини виключаються з сегментів; статистика показується користувачу.
6. Кожна функція `openpid-dsp` має: (a) тест проти еталону NumPy/SciPy з `tools/reference` (фікстури в репозиторії), (b) property‑тести інваріантів (Парсеваль, лінійність, роундтрип), (c) тести граничних випадків (порожні/короткі ряди, константа, одна прогалина).
7. Допуски: ≤1e‑9 відносно для лінійних перетворень, ≤1e‑6 для ітеративних/згладжуваних.
8. Детермінованість: один і той самий лог + параметри → побітово ідентичний JSON‑вихід на всіх ОС (golden‑тести в CI на трьох платформах).

## Наслідки
- Python потрібен лише розробникам для регенерації фікстур; у рантаймі та збірці його немає.
- Зміна алгоритму вимагає оновлення golden‑файлів із поясненням у PR.
