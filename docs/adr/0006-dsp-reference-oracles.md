# ADR-0006: Reference oracles for the mathematics (`openpid-dsp`, `openpid-analysis`)

Status: accepted (2026-11-04, rewritten 2026-11-11)

## Context
The first decision gave every `openpid-dsp` function a fixture computed by NumPy / SciPy. That fixes the functions, not what a user reads: a fixture written from the same formula as the code cannot show that the formula is the wrong one (the deconvolution fixture is our own formula again in Python), and no test fixed a level above the DSP layer (`docs/calibration/INVENTORY.md`, open points). The owner (2026-11-11): not everything is computed correctly; the results have to be checked against the reference tool the project is modelled on, on logs whose content is known (#166).

## Decision
Three oracles, each for what the others cannot say:

1. **The specification in NumPy / SciPy.** Every `openpid-dsp` function has a test against a fixture generated by `tools/reference/make_fixtures.py` (NumPy 2.5 / SciPy 1.18). The script implements the *specification* of the algorithm independently of the Rust code (for the windows, Welch and rfft directly the SciPy/NumPy functions; for the deconvolution and the heatmap an own implementation of the formulas from `docs/DESIGN.md`). The fixtures (`tests/reference/*.json`, ~0.6 MB) are committed, so CI needs no Python. Tolerances: 1e-12 relative for the windows and the FFT, 1e-10 for Welch, 1e-9 for the deconvolution (accumulation in cumsum).
2. **The exact answer of a synthetic probe.** `crates/openpid-probe` builds flights whose content is known in closed form: tones evaluated from their formula, noise of a given power, the response to stick steps as the sum of the plant's analytic step responses. They are written as Betaflight logs (`openpid_fmt_blackbox::write`) and analysed as any log. What OpenPID shows for them is compared with what is true: the level of a tone, the density of noise, an overshoot, a delay. This is the oracle for the analyses and for everything between the DSP function and the screen (segment rounding, averaging, normalisation, decibels).
3. **The behaviour of the reference tool on the same probes.** The pack of a round (`openpid-probe pack <round>`: the logs, `manifest.json` with the truth, `ours.json` with OpenPID's results) is opened in the reference tool by the owner; the numbers read from its screens are stored in `tests/calibration/`. Where the three disagree (the reference tool, OpenPID, the exact value) the case is an entry of `docs/calibration/DECISIONS.md` and the owner chooses; OpenPID's behaviour changes only then.

On top, as before, tests of physical meaning (Parseval, the amplitude of a sine, recovery of a PT1 plant by deconvolution, the metrics of ideal step responses) and plausibility on real logs.

What may and may not be taken from the reference tool: only what it shows for a log. None of its code is read, copied or linked (`CLAUDE.md`); its screenshots are not committed, only the numbers read from them; code and file names do not carry its name.

`openpid-probe` is a workspace crate, not a Python tool: it needs the simulator's session model, the Blackbox encoders and the analyses directly, and a Python tool would need a second log writer and could reach the analyses only through the CLI. It has no dependency outside the workspace beyond `serde`, `serde_json` and `thiserror`, which the workspace already uses. It is tested and counts towards coverage like the other crates; it is not part of a release archive.

## Consequences
- An algorithm change = a script change plus regenerated fixtures in one PR (oracle 1), and the probe tests that fix the levels a user reads (oracle 2); CI catches a mismatch.
- Python stays a dev-only dependency, for oracle 1.
- A pack is a pure function of the round and the commit: the same bytes on every build, so a reading can be traced to its log. The probes of a round that has been run are not changed afterwards; a new question is a new probe in a later round (`docs/calibration/ROUNDS.md`).
- A log keeps whole deg/s. The exact answer of a probe is therefore stated for the logged samples too (the manifest's `logged_*` values), and probes carry a little noise so that the rounding error is noise as well.
- Oracle 3 needs the owner: every round is a session with the reference tool. An area is closed after at least three rounds, the last without a change.
